# Розгортання Slovnuk

Порядок кроків не випадковий: кожен спирається на попередній. Найчастіша
помилка — імпортувати 608 карток раніше, ніж на бойовому домені взагалі
з'явився активований акаунт, у який їх класти.

Чому топологія саме така (два Caddy послідовно) — [ADR-0015](adr/0015-dva-caddy-i-spilna-merezha.md).

---

## 0. Що потрібно мати

- Сервер із Docker і `docker compose` (v2).
- A-запис `slovnuk.ivankhomych.com` на IP сервера. **До появи запису Caddy
  сертифіката не отримає** — Let's Encrypt перевіряє домен запитом ззовні.
- Відкриті `80` і `443`. Порт 80 потрібен не лише для перенаправлення: через
  нього йде ACME-перевірка.
- Домен, підтверджений у Resend, і `RESEND_API_KEY`. Без цього реєстрація
  формально працює, але лист активації нікуди не приходить, і акаунт лишається
  неактивованим назавжди.

---

## 1. Спільний Caddy (один раз на сервер)

Цю теку (`deploy`) винести з репозиторію Slovnuk у власний каталог — вона
нічия, а не Slovnuk'ова. Далі приклади припускають `~/infra/caddy`.

```bash
docker network create web          # мережа, у якій зустрічаються всі проекти
cd ~/infra/caddy
docker compose up -d
```

Перевірка: `docker compose logs caddy`. Помилок про сертифікат бути не мусить —
але їх і не буде, доки на `web` немає контейнера `slovnuk-frontend`. Caddy
спокійно чекає.

## 2. Slovnuk

```bash
git clone <repo> slovnuk && cd slovnuk
cp .env.example .env
```

У `.env` **обов'язково** змінити, інакше або не підніметься, або підніметься
зламаним:

| Змінна | Значення | Що буде, якщо не змінити |
|---|---|---|
| `SECRET_KEY_ACCESS` | `python -c "import secrets; print(secrets.token_urlsafe(64))"` | Застосунок не стартує — так і задумано |
| `SECRET_KEY_REFRESH` | те саме, **інше** значення | Те саме |
| `POSTGRES_PASSWORD` | свій | База з паролем `slovnuk` |
| `MINIO_ROOT_USER` / `MINIO_ROOT_PASSWORD` | свої | Сховище з `minioadmin` |
| `S3_STORAGE_PUBLIC_ENDPOINT` | `https://slovnuk.ivankhomych.com/media` | **Аватар мовчки не завантажується**: http-адреса на https-сторінці блокується браузером як mixed content |
| `FRONTEND_BASE_URL` | `https://slovnuk.ivankhomych.com` | Листи активації ведуть на `localhost:5173` |
| `RESEND_API_KEY`, `EMAIL_SENDER` | свої | Листів немає взагалі |
| `ANTHROPIC_API_KEY` | свій, або лишити порожнім | Порожній — заповнення картки з ШІ на цьому сервері немає ні в кого; це нормальний стан, а не поломка |

`S3_STORAGE_ENDPOINT` лишається `http://minio:9000` — це адреса **всередині**
docker-мережі, і вона правильна. Плутати їх легко, наслідки різні: перша — як
бекенд ходить у сховище, друга — яку адресу віддають браузеру.

`POSTGRES_HOST` у `.env` теж лишається `localhost`: сервіс `backend` перекриває
його на `postgres` сам.

Підйом:

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
```

`alembic upgrade head` виконує entrypoint бекенда сам, перед `uvicorn`.

Перевірка — саме в цьому порядку, бо кожна наступна залежить від попередньої:

```bash
docker compose ps                                  # усі healthy
curl -I https://slovnuk.ivankhomych.com/           # 200, сертифікат живий
curl -s https://slovnuk.ivankhomych.com/api/v1/... # API через той самий домен
curl -I https://slovnuk.ivankhomych.com/accounts/activate   # 200, а не 404
```

Останній рядок перевіряє `try_files`: цієї сторінки немає на диску, і саме на
неї веде посилання з листа активації.

## 3. Перший акаунт

Через сам застосунок: відкрити домен → «Створити акаунт» → лист → активація.

Робити це **до** імпорту. Скрипт шукає користувача за поштою і без нього
просто впаде.

---

## 4. Бойовий імпорт 608 карток

Файл експорту в git **не лежить** (`.gitignore`), тож його треба привезти:

```bash
scp "slovnyk-2026-07-27 (1).json" server:~/slovnuk/legacy.json
```

Запуск відрізняється від локального, і навмисно: на машині розробника скрипт
крутиться з хоста, бо там уже є Python із залежностями.
На сервері його немає й не треба — беремо готовий образ бекенда, а скрипт і
файл вкидаємо томами. В образ вони не копіюються (ADR-0002).

**Спершу завжди пробний запуск:**

```bash
cd ~/slovnuk
docker compose run --rm --entrypoint python \
  -v "$PWD/backend/scripts:/app/scripts:ro" \
  -v "$PWD/legacy.json:/data/legacy.json:ro" \
  backend -m scripts.import_legacy \
  --file legacy.json --email ivan.khomychh@gmail.com --dry-run
  
  
docker compose run --rm --entrypoint python \
  -v "$PWD/backend/scripts:/app/scripts:ro" \
  -v "$PWD/legacy.json:/data/legacy.json:ro" \
  backend -m scripts.import_legacy \
  --file /data/legacy.json --email <ваша-пошта> --dry-run
```

`--dry-run` показує звіт і відкочує транзакцію. Якщо звіт влаштовує — та сама
команда без `--dry-run`.

**Що в звіті мусить бути і не є помилкою:**

- `notes_skipped_empty: 1` — нотатка `mrp1z5i7krkod` не має заголовка взагалі,
  тож приїде 8 нотаток із 9. Це відоме й свідоме (`HANDOFF.md`, «Відкриті
  питання»).
  Дві фрази її тіла швидше перенабрати в застосунку, ніж правити скрипт.
- Усі 705 доріжок одразу прострочені (`due_at = now`). Так і має бути: прогрес
  зі старого PWA не переноситься (ADR-0001), і день імпорту буде сплеском у
  календарі — це правда, а не артефакт.

Скрипт ідемпотентний: списки зіставляються за назвою, картки — за
нормалізованим словом. Повторний запуск оновлює, а не дублює, і наявних
доріжок не чіпає.

Тема, акцент, озвучення й денні цілі не переносяться — виставляються руками в
профілі.

## 5. Оновлення

```bash
cd ~/slovnuk
git pull
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
```

Якщо мінялись Pydantic-схеми, `frontend/src/api/schema.d.ts` мусить бути
перегенерований **до коміту** (`../frontend/README.md`) — він у git саме тому, що
інакше образ фронтенду не збереться в чистій копії.

## 6. Доступ до ШІ

Заповнення картки з ШІ бачать не всі: це привілей, виданий адресно (ADR-0026).
Дві умови незалежні — `ANTHROPIC_API_KEY` вирішує, чи є фіча **на цьому
сервері**, а `ai_access` — чи можна **цій людині**. Немає котрої з двох — кнопки
немає.

Видається з машини розробника, через SSH-тунель до Postgres, як і оптимізатор
(ADR-0002):

```bash
ssh -N -L 5432:127.0.0.1:5432 user@server &
cd backend
python -m scripts.ai_access list
python -m scripts.ai_access grant --email friend@example.com --by me@example.com --note "тестує форми"
python -m scripts.ai_access revoke --email friend@example.com
```

`list` показує ще й витрати: скільки звернень зробила людина і скільки слів
заповнила. Числа різні, бо невдалі звернення теж коштували вхідних токенів
(ADR-0028).

Транскрипція — окремою підкомандою, бо це преференція людини, а не частина
ШІ-доступу: її можна поставити й тому, кому ШІ не видано.

```bash
python -m scripts.ai_access transcription --email me@example.com --value us
```

Діє на нові пропозиції; уже створені картки лишаються як були.

## Чого тут немає

**Резервних копій.** Свідоме рішення власника, а не недогляд. Ціна відома:
`postgres_data` зберігає `review_logs`, які не відновлюються нічим — синтезувати
їх заборонено (`../CONTEXT.md`), а оптимізатору потрібно півтора-два місяці їхнього
накопичення (ADR-0002). Втрата тому означає не лише втрату даних, а й перезапуск
цього відліку з нуля. Мінімум, коли дійдуть руки: `pg_dump` по cron плюс копія
поза цією машиною.

**Доступу до бази ззовні.** Postgres слухає `127.0.0.1:5432`, тобто тільки з
самого сервера або через SSH-тунель — саме так, як передбачає ADR-0002 для
оптимізатора:

```bash
ssh -L 5432:127.0.0.1:5432 server
```

Те саме стосується консолі MinIO (`127.0.0.1:9001`) і бекенда напряму
(`127.0.0.1:8000`, в обхід TLS).
